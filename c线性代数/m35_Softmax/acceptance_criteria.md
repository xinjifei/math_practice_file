# 第 35 天验收标准

## 体系定位
- 所处阶段：线性代数基础（AI 数学模块），第 12/16 天。前面 m24~m34 从向量一路走到 Embedding，全都在回答"**怎么把东西表示成向量**"。
- 今天的概念在这个阶段的角色：**视角切换点**。从今天起问题变了——不再是"怎么表示"，而是"**这些数字怎么变成决策**"。Softmax 是"推理端的最后一步"：模型内部算出的原始分数（logits），经过它才变成能用的概率。
- 和目标的关系：这是**技术判断力**的拼图——temperature 是你在调用任何 LLM API 时都要填的参数。不知道它是"对分数的缩放"，你就只能靠玄学调参；知道它，你就能预判"调大调小会发生什么"。

## AI 分界线
- **归你（必须长在脑子里）**：
  - "任意实数分数 → 概率分布"这个转换的心智模型（输入没有约束，输出有约束）
  - 为什么必须用 eˣ 而不是直接除以总和
  - temperature = 对分数差距的**缩放**，T 小→赢家通吃，T 大→摊平均匀
  - 拿到一组概率，能判断它是"确定"还是"随机"——这个判断力在 Day 37 熵会立刻用到
- **可外包（概念要知道、实现交给 AI）**：
  - numpy 实现的具体写法、批量版本的 `axis` 参数
  - 数值稳定性的代码处理（减 max）
  - softmax 的梯度推导（教材明确说了不需要）

- [ ] 硬线1：能说清 Softmax 的**输入和输出**——输入是任意实数（可正可负、可大可小、和不为 1），输出是概率分布（每项 ∈ (0,1)、总和 = 1）。**并且能回答：为什么不直接 `x / x.sum()`？** 指数到底干了什么？（要能指出普通除法的致命伤：负数会算出负的"概率"）
- [ ] 硬线2：能说清 **temperature 的机制**——T 是把分数除以 T 再送进 softmax，本质是**缩放分数之间的差距**，不是什么玄学的"随机度旋钮"。要能推出：T→0 时差距被放大到极大 → 最大项吃掉几乎全部概率（趋近 argmax）；T→∞ 时差距被压平 → 趋近均匀分布。并能对上 LLM 里 temperature=0.1 vs 1.5 的实际体感
- [ ] 硬线3：能说清 Softmax 产出的这个"概率分布"在 AI 里是**什么角色**——它不是数学题里的中间量，而是**模型做决策前的最后状态**：LLM 每吐一个 token，就是在 Softmax 出来的这个分布上按概率"抽签"（temperature 就是在这个抽签点上起作用）。能从"我在调 API"这个角度说清：为什么模型不直接把最可能的词给你，而是先给你一个分布
