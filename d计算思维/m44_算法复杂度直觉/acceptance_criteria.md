# 第 44 天验收标准

## 体系定位 
- 模块「计算思维数学」第 5/13 天。前四天（40–43）学的是**怎么给收益和风险称重**——都是"数字算得对不对"；今天第一次把注意力转到"算得动算不动"。
- 角色：给"快慢"这件事一把尺子。之前你写循环只管结果对不对，今天开始要知道这段循环在数据变大时会不会死。这个模块后半段还会反复出现"同一件事要跑成千上万次"的场景，届时判断"扛不扛得住"靠的就是今天建立的直觉。
- 和目标的关系：技术判断力。Big O 的真正价值不是会算复杂度，而是**写之前**就能判断"这个写法数据一大就炸"，以及读别人的代码时一眼认出"这里套了两层循环"。

## 硬线（不过不能结束，达标看 note.md 写没写到位）
- [ ] 硬线1：能说清 Big O 量的**不是秒数，是增长趋势**。并用这一点解释两件事：① 同一段代码换台慢机器，测出的秒数变了、复杂度没变；② n 很小时 O(n²) 完全可能比 O(log n) 快（常数项在起作用），所以"小数据上测出来快"不能证明算法好。
- [ ] 硬线2：能说清 O(log n) 的"对半砍"是从哪来的：为什么二分**必须**先有序；为什么 n 从 1000 涨到 100 万（×1000），二分只多约 10 次对半，而线性查找要多 1000 倍。把"多一个 0 只多约 3 次对半"变成能脱口而出的数字直觉。
- [ ] 硬线3：能在自己写过的代码里认出复杂度——一重 for/遍历 = O(n)，外层循环里再套一次遍历 = O(n²)，"按位置找第几个" vs "按 key 直接取" = O(n) vs O(1)。并能对着**一段具体代码**说出：n 从 100 涨到 100 万时，哪一段先炸、大概慢多少个数量级（提示：O(n²) 是 n 涨 1 万倍 → 耗时涨 1 亿倍）。
