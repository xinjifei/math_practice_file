## 举例：
> 同样的数据，同样的任务，不同的算法
```
#任务：找到用户名在列表中的位置
users = 用户名列表（已经排好序）
列表长度 = 1024
```
- 算法1：遍历整个列表，识别到指定用户名后，输出下标
- 算法2：每次将列表一分为二，判断用户在哪边，然后去用户存在的那个一半的列表里再次重复

- 比较两种算法的最坏可能性
    1. 用户正好在最后面，找1024次
    2. 不管用户在哪里都是找10次

- 用数字写出来两种算法的耗时增长趋势
```
n = 数据长度
1、增长趋势 = n
2、增长趋势 = log(n)
```
## bigO
- 再看一个例子：
```
#这是一个算法的运行时间计算公式
T(n)=3n^2+5n+100
```
- 当n越来越大时，每个项对时间的影响：
1. 3n^2：越来越大，增长速度最快
2. 5n：影响越来越小
3. 100：几乎可以忽略不计

- 这个例子，bigO就是
$$
O(n^2)
$$
> bigO可以理解为：忽略常数倍和低阶项，抓住对增长影响最主要的部分。而不是算法的运行时间函数

- 因此，有两个现象：
    1. 换了机器，bigO一样，但是运行时间不同。因为bigO只代表理想化的复杂程度
    2. n非常小时，O(n²) 有可能比 O(log n) 运行的要更快，因为算法复杂度的常数项起的作用可能会盖过指数的作用
> 说明两件事情：1、不能一看到bigO就断定某个算法肯定快。2、对于小数据，不能比较算法运行时间来对比他们的复杂程度

- 另外还有两种经典的算法对应的两种bigO
    1. 字典直接取值，字典多长都不影响时间:O(1)
    2. 枚举数据的所有组合方式（包括空组合）：O(2^n)

## 二分算法
### 数据必须有序
- 最上面的第二个例子使用的是“二分算法”。它的核心在于可以通过数据“切面”的大小来判断目标数据在被切分的哪一边，但是这要求数据本身排列是有序的，否则数据切面无法说明任何事情
```
举例：
数据1 = [2, 5, 9, 12, 17, 21, 30]
数据2 = [21, 5, 9, 12, 2, 30, 17]
# 目的：找到21
```
- 套完二分算法发现数据必须有序
### 二分的数学特性
- 二分法的次数可以理解为
> 每次提问只获得”是“或者”否“的答案，需要问多少次才能表达n中的一个数字.  
> 用数学的方法表示：log_2(n)。串联到main线的信息熵
- 按照这个算法:n从1000涨到100万，二分只多10次，而线性查找要多1000倍(bigO=O(n))
- 还有一个心算小窍门：当数据每多一个0（乘10），二分法次数就会多三次左右（因为log(10)约等于3）
